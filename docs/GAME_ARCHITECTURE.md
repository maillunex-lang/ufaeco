# Архитектура БАШЭКО Online

> **Статус документа (версия 2 дорожной карты).** Разделы про сервер, протокол, сессии, журнал операций и клиент описывают
> реализованный фундамент (этап 0). Разделы «Экономика (этап 3)», «Карта города», «Здания» описывают **прототип**, который будет
> заменён механиками Capitalism 2 (см. [ROADMAP.md](../ROADMAP.md), [GAME_DESIGN.md](GAME_DESIGN.md), [TIME_MODEL.md](TIME_MODEL.md)).

## Целевая архитектура

```
Godot-клиент (Android) ──WebSocket──► Игровой сервер (авторитетный)
                                          ├── Команды игроков и ИИ (единый слой, идемпотентность, права)
                                          ├── Часы мира и недельный тик (каждые 6 ч; месяц с 09:00 по Уфе)
                                          │     фазы: стройка → добыча → производство → поставки → розница →
                                          │           аренда/зарплаты → ИИ и политики → события
                                          │     месяц: налоги, проценты, отчёты, макро, города; год: итоги
                                          ├── Домены: компании и учёт, карта РБ и города, здания, добыча и фермы,
                                          │           заводы, поставки и логистика, розница и спрос, бренд, НИОКР,
                                          │           персонал и управление, недвижимость, финансы и акции
                                          ├── ИИ-игроки (те же команды, персоны и сложность)
                                          └── Данные игры (JSON): города, ресурсы, товары, рецепты, здания, технологии
                                                    ↓
                                       PostgreSQL: состояние мира, ledger, аудит, журнал тиков
```

Принципы: сервер — единственный источник истины (деньги, товары, собственность, время); тик детерминирован по
`(seed, номер тика)`; торговля — договоры и розница, без биржи заказов; данные отделены от кода.

## Слои системы

```
Android Godot Client
```

## Выбранный стек

| Часть | Технологии |
|---|---|
| Клиент | Godot 4, `gl_compatibility`, Android |
| Backend | TypeScript, Node.js ≥ 20, Fastify, WebSocket (`ws`) |
| Валидация протокола | Zod (строгие схемы, лишние поля запрещены) |
| База данных | PostgreSQL 16 через `pg`, SQL-миграции (`server/migrations`) |
| Тесты | Vitest + реальный PostgreSQL |

Не используются: NestJS, Redis, Kubernetes, микросервисы. Один процесс, модульный монолит.

## Модули сервера (`server/src`)

- `accounts` (гость, регистрация, вход), `sessions`, `world`, `companies` (компании, журнал баланса, инвентарь, предприятия), `commands` (реестр команд) — реализованы (этапы 1–2);
- `market`, `contracts`, `real_estate` — только интерфейсы, функциональности нет;
- `persistence` (pool, транзакции, миграции, audit, идемпотентность), `protocol` (Zod-схемы), `security` (rate limiter, токены), `net` (WebSocket-шлюз).

## Протокол

Единый формат описан в [protocol/README.md](../protocol/README.md), константы — `protocol/protocol.json`
(их читают сервер и Godot-клиент). Конверт: `protocol_version`, `message_id`, `type`, `request_id`, `payload`.
Типы: `hello`, `auth`, `auth_ok`, `heartbeat`, `world_snapshot`, `command`, `command_result`, `error`, `disconnect`, `reconnect`.

- Сессии: `auth` создаёт гостевого игрока и сессию; `resume_token` хранится в БД только как sha256 и ротируется при каждом `reconnect`.
- Идемпотентность: `command` требует `request_id`; пара `(player_id, request_id)` выполняется ровно один раз (резерв, выполнение и ответ — в одной транзакции).
- Тик мира (`TICK_RATE`) и рассылка snapshots (`SNAPSHOT_RATE`) общие для всех клиентов.
- Защита: rate limit на соединение, лимит размера сообщения, таймаут авторизации, heartbeat-таймаут.

## Экономика прототипа — удалена (этап 1)

Прежний «экономический день» (рецепты предприятий, зарплаты, NPC-торговый дом, налог с розницы, кредиты, банкротства, цены по спросу/предложению)
удалён: он заменён игровыми часами и недельным тиком ([TIME_MODEL.md](TIME_MODEL.md)). Настоящие механики Capitalism 2 добавляются этапами 5–14.
Остаётся казна как получатель платежей за землю.

## Карта города на сетке (этап 2.5)

`server/src/world_map`: `generator.ts` — детерминированный генератор (seed + номер тика) на клетках, `growth.ts` — рост города, `service.ts` — хранение,
покупка клеток, постройка и снос зданий, тик города.

**Сетка.** Тайлы `.` земля, `#` дорога, `~` вода, `=` мост — целые клетки. Здание — прямоугольник W×H клеток. Занятость зданиями — `building_cells`
(PK по клетке: пересечения невозможны в БД), владение землёй — `parcels` (PK по клетке). Зона, стоимость земли и трафик клетки вычисляются
детерминированно по координатам (шум + центральность) и не хранятся; цена клетки = база города × (0,35 + 1,65 × стоимость земли/100) × рыночный множитель
(зависит от населения). Покупаемая клетка — земля не дальше 4 клеток от дороги, не парк, без здания и владельца.

**Покупка и постройка.** `buyCells`: проверки → вставка клеток (`ON CONFLICT DO NOTHING`, число вставленных должно совпасть с площадью, иначе откат) →
списание и платёж в казну через журнал. `placeBuilding`: габариты из каталога (с поворотом), клетки куплены этой компанией, нет зданий, зона каждой клетки
подходит виду, затем вставка здания и клеток и списание стоимости (гонка за клетки решается PK `building_cells`).

**Городская застройка (NPC).** 13 типов (дом 1×1 … завод 3×3) с габаритами и этажностью; `placeNpcBuilding` ставит здание у улицы в клетках своей зоны, крупные типы — ближе к центру.
Тик города: население тянется к цели (жильё + рабочие места), очки строительства → новые здания, а при нехватке места — этажи; нехватка фронта застройки
или места в нужной зоне → новые улицы (с уклоном к нужному району). Частные клетки город не трогает.

**Регион на сетке** (`region/grid.ts`): ячейка ≈ 8 км; маска региона и реки (из контура Natural Earth), города занимают 3×3/2×2/1×1 ячейки (спиральный поиск
свободного места), месторождения — по ячейке, дороги и ж/д — цепочки ячеек (Брезенхем). Расстояния и фрахт — по реальным координатам.

Клиент: `scripts/map/city_map_view.gd` (клетки, здания по габаритам, слои, предпросмотр), `scripts/map/region_map_view.gd` (сетка региона), `scripts/main.gd` (панели и команды).

## Деньги и журнал

Баланс компании меняется только в `CompanyService.credit/debit` внутри транзакции команды; списание атомарно
(`UPDATE … WHERE balance_cents >= сумма`), каждая операция пишет строку в `ledger_entries`
(инвариант: баланс = сумма записей). Проверка прав владельца — в сервисе, а не в клиенте.

## Принцип авторитетности

Клиент отправляет только намерение:

- купить товар;
- продать товар;
- арендовать помещение;
- заключить контракт;
- построить предприятие.

Сервер проверяет:

- личность игрока;
- права компании;
- баланс;
- наличие товара;
- доступность помещения;
- цену;
- срок;
- повтор запроса.

Только сервер изменяет деньги, товары, контракты, здания и собственность.

## Общий мир

Все игроки используют одну экономическую модель. Зоны карты являются техническими границами нагрузки, но рынок, контракты и цены общие для всех регионов.

## Недвижимость

Жилой дом состоит из отдельных units:

- квартиры;
- магазины;
- кафе;
- аптеки;
- офисы;
- сервисные помещения.

Игрок может владеть домом, сдавать помещение или арендовать его у другого игрока.

## Экономический цикл

```
Сырьё → Производство → Склад → Логистика → Магазин → Жители
```

Каждое действие создаёт серверную транзакцию и записывается в журнал.

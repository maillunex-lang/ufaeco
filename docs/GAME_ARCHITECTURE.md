# Архитектура БАШЭКО Online

## Слои системы

```
Android Godot Client
        ↓ WebSocket
Authoritative Online Server
        ↓
Game Services
        ├── Accounts
        ├── Companies
        ├── Market
        ├── Contracts
        ├── Production
        ├── Logistics
        ├── Real Estate
        └── World Events
        ↓
PostgreSQL / Durable Ledger
```

## Выбранный стек

| Часть | Технологии |
|---|---|
| Клиент | Godot 4, `gl_compatibility`, Android |
| Backend | TypeScript, Node.js ≥ 20, Fastify, WebSocket (`ws`) |
| Валидация протокола | Zod (строгие схемы, лишние поля запрещены) |
| База данных | PostgreSQL 16 через `pg`, SQL-миграции (`server/migrations`) |
| Тесты | Vitest + реальный PostgreSQL |

Не используются: NestJS, Redis, Kubernetes, микросервисы. Один процесс, модульный монолит.

## Модули сервера (`server/src`)

- `accounts` (гость, регистрация, вход), `sessions`, `world`, `companies` (компании, журнал баланса, инвентарь, предприятия), `commands` (реестр команд) — реализованы (этапы 1–2);
- `market`, `contracts`, `real_estate` — только интерфейсы, функциональности нет;
- `persistence` (pool, транзакции, миграции, audit, идемпотентность), `protocol` (Zod-схемы), `security` (rate limiter, токены), `net` (WebSocket-шлюз).

## Протокол

Единый формат описан в [protocol/README.md](../protocol/README.md), константы — `protocol/protocol.json`
(их читают сервер и Godot-клиент). Конверт: `protocol_version`, `message_id`, `type`, `request_id`, `payload`.
Типы: `hello`, `auth`, `auth_ok`, `heartbeat`, `world_snapshot`, `command`, `command_result`, `error`, `disconnect`, `reconnect`.

- Сессии: `auth` создаёт гостевого игрока и сессию; `resume_token` хранится в БД только как sha256 и ротируется при каждом `reconnect`.
- Идемпотентность: `command` требует `request_id`; пара `(player_id, request_id)` выполняется ровно один раз (резерв, выполнение и ответ — в одной транзакции).
- Тик мира (`TICK_RATE`) и рассылка snapshots (`SNAPSHOT_RATE`) общие для всех клиентов.
- Защита: rate limit на соединение, лимит размера сообщения, таймаут авторизации, heartbeat-таймаут.

## Экономика (этап 3)

Модуль `server/src/economy`: каталог параметров (`catalog.ts`), чистая функция цен (`pricing.ts`), сервис (`service.ts`).

**Экономический день** — один атомарный проход в транзакции под advisory-локом (`runDay`), по умолчанию каждые
`ECONOMY_DAY_TICKS` тиков мира: зарплаты → производство по рецептам → розница жителям (доли магазинов пропорциональны
предложению) → налоги в казну → проценты по кредитам → проверка банкротств → пересчёт цен. Ошибка откатывает весь день.

**Цены**: `новая = цена·(1 + clamp(0,25·(спрос−предложение)/max, ±10%))`, затем возврат к базе на 5%, границы ×0,4…×3.
Спрос и предложение — сумма за день: производство/потребление, продажи жителям, сделки игроков с NPC + фон 100 ед.

**NPC-компании** (казна, банк, торговый дом) — обычные компании с `is_npc`, без владельца; их деньги идут тем же
журналом. Ликвидность NPC поддерживается записями `npc_endowment`.

**Денежная масса**: источники — стартовый капитал, выручка от жителей, кредиты, эмиссия NPC; стоки — зарплаты, налоги
(копятся в казне). Сейчас это модель без доходов жителей: параметры не калиброваны.

**Игроки не торгуют друг с другом** до этапа 4: доступна только торговля с NPC-торговым домом.

## Карта города

`server/src/world_map`: `generator.ts` — чистый детерминированный генератор по seed; `service.ts` — сохранение и покупка.
Сетка 45×30 тайлов: дороги каждые 5 тайлов, кварталы 4×4, в квартале 4 участка 2×2; река пересекает город по вертикали,
дороги через неё — мосты. Зоны: коммерческий центр, промзона на востоке, парки (не продаются), остальное жильё.
Тайлы хранятся в `cities.tiles` (jsonb), участки — в `map_lots`; владелец участка — компания. Покупка — транзакция:
блокировка строки участка → списание с компании → зачисление в казну → смена владельца.

Клиент: `scripts/map/city_map_view.gd` (рисование, сдвиг, масштаб, выбор), `scripts/main.gd` (связь с сервером и панель участка).

## Деньги и журнал

Баланс компании меняется только в `CompanyService.credit/debit` внутри транзакции команды; списание атомарно
(`UPDATE … WHERE balance_cents >= сумма`), каждая операция пишет строку в `ledger_entries`
(инвариант: баланс = сумма записей). Проверка прав владельца — в сервисе, а не в клиенте.

## Принцип авторитетности

Клиент отправляет только намерение:

- купить товар;
- продать товар;
- арендовать помещение;
- заключить контракт;
- построить предприятие.

Сервер проверяет:

- личность игрока;
- права компании;
- баланс;
- наличие товара;
- доступность помещения;
- цену;
- срок;
- повтор запроса.

Только сервер изменяет деньги, товары, контракты, здания и собственность.

## Общий мир

Все игроки используют одну экономическую модель. Зоны карты являются техническими границами нагрузки, но рынок, контракты и цены общие для всех регионов.

## Недвижимость

Жилой дом состоит из отдельных units:

- квартиры;
- магазины;
- кафе;
- аптеки;
- офисы;
- сервисные помещения.

Игрок может владеть домом, сдавать помещение или арендовать его у другого игрока.

## Экономический цикл

```
Сырьё → Производство → Склад → Логистика → Магазин → Жители
```

Каждое действие создаёт серверную транзакцию и записывается в журнал.
